## 一、阶段判断

阶段二已经真实证明了外部身体循环：同一个构建产物能够部署到独立 agent 卷，随 Ubuntu 重启自动运行，异常退出后由 systemd 恢复，停止后离机保存，reset 后进入干净实例；root、网络、模型、Chrome、Playwright MCP、微信和 LVM 恢复也已经分别得到实机验证。

因此阶段三不再重复建设部署系统、观察平台、系统恢复和图形工具，也不开始实现完整 AIP、Concern、Narrative Self 或正式出生说明。它只把阶段二的机械心跳替换为第一条能够接收外部信号并向外回应的认知—行动运行脊柱：

```text
身体、时间与资源 → Fact Snapshot → Difference Gate ┐
Codex 导师文字 ─────────────────────────────────────┤
模型、动作与系统结果 ───────────────────────────────┘
                                      ↓
                                  Event Inlet
                                      → 持续 Pulse / Background
                                      → 唯一认知租约
                                      → 一次真实模型认知
                                      → 至多一个 Shell 或导师回复动作
                                      → 真实结果返回 Event Inlet
```

这个闭环是后续所有生命动力学的共同承载面。阶段三仍是工程耐久实验，不生成 `T0`、`aliceMMDD<letter>` 或正式 Proto-Hominal 代，也不根据这一阶段判断 alice 是否已经形成生命表现。

## 二、唯一目标

在目标 Ubuntu 上运行一个极小的 `hominald`：它能持续取得少量身体事实，只把实质变化送入统一事件入口；Codex 能通过 SSH 保护的导师专用接口向它发送文字；模型请求和身体动作进行时生命脉冲持续；同一时刻只有一个认知结果能够提交；Shell 或导师回复的结果能回到发起它的认知链；进程崩溃后从同一实例继续，不遗失事实，也不盲目重复结果未知的动作。

阶段完成以后，我们应当可以直接在这条脊柱中加入 AIP、内生价值、Concern 和注意竞争，而无需再次改变部署、进程、并发、动作回链和恢复方式。

## 三、最小实现

### 1. 一个进程、一个状态所有者

新增正式入口 `body/cmd/hominald`。进程内只有一个事件循环能够改变当前 revision、认知租约、动作状态和恢复状态。时钟、导师消息、模型请求和 Shell 动作都通过同一个事件入口进入；接口处理、模型请求和动作可以在后台等待，但只能把事实送回事件循环，由事件循环按顺序提交。

代码先保持在一个运行包中，用少量文件分开入口、循环、模型、动作和持久化，不建立 `Planner`、`Reviewer`、`Emotion Agent`、消息总线或按认知术语拆分的 package。只有真实复杂度已经出现时才继续拆分。

### 2. 五秒生命脉冲

沿用已经验证的五秒心跳节律，ready 状态下相邻有效 Pulse 的最大间隔为十秒。Pulse 只做三件事：更新时间与身体余量、接收已完成事件、原子更新存活状态。

无变化 Pulse 不调用模型、不追加思想日志。模型调用持续超过十秒或 Shell 进程仍在运行时，Pulse 仍由事件循环继续推进。

### 2.1 最小感知面与事实差分

阶段三建立身体事实进入生命循环的最短路径，但不实现 AIP，也不判断事实对 alice 的意义：

```text
Sense → Fact Snapshot → Difference Gate → Event Inlet
```

每次 Pulse 取得低成本事实：单调时间、系统 uptime、本地模型额度账本、未决动作与相关进程状态。磁盘余量、网络可用性以及桌面、Chrome、Playwright MCP、微信等身体器官采用较慢巡检或在实际使用前检查，不为维持五秒节律持续发起网络请求和图形探测。

Difference Gate 只比较新旧事实、识别状态变化、越阈变化和首次出现的异常。它保存原始值、观察时间和事实来源；时间流逝本身只推进 Pulse，不每五秒制造一个认知事件。相同事实重读、微小抖动和重复回执被合并，只有实质变化形成 `body_delta`、`continuity_event` 或对应结果 Event。

导师文字和动作结果本身已经是离散事实，直接进入 Event Inlet。阶段三不监听整个文件系统，不自动抓取公开网络，不持续读取浏览器或微信内容，也不注入随机刺激。以后 alice 主动观察网页、文件、进程或其他出口时，所得结果仍通过同一 Action → Reality Event 路径返回。

### 3. 唯一认知租约

一次模型认知获得一个包含 `instance_id`、`revision` 和 `pulse_id` 的租约。租约在途时，新触发只进入背景事件，不启动第二次模型认知。结果返回时只有租约仍然匹配才能提交；被明确中止或已经过期的结果保留为迟到事实，不覆盖当前状态。

阶段三不实现真正的 Focal Workspace 选择。工程测试使用一条真实导师消息或一个明确测试事件形成唯一测试焦点，用它验证单线程、迟到结果和动作回链；导师消息如何与其他现实、关系和内部张力竞争注意属于阶段四。

### 4. 两种最小外部动作

接入当前 `xconfigs/hominal/xconfig.yaml` 已配置的 Responses API。工程焦点允许模型自由给出简短最终回应，并可选择调用一次 `body_shell` 或 `mentor_send`。每个焦点仍然至多形成一个新动作，不把导师回复作为隐藏的第二次输出。

`body_shell` 执行 root Shell，用于验证身体动作。若发生工具调用：

1. 事件循环先保存动作请求和实际命令；
2. root Shell 执行命令，保留退出码、标准输出、标准错误和实际文件结果；
3. 结果以同一个关联标识返回模型；
4. 模型完成本次认知，事件循环提交最终结果并释放租约。

这里的工具边界需要极小的机器结构，因为命令、关联标识和退出结果必须准确；模型对事实的理解和最终表达仍使用自然语言，不记录隐藏思维链，也不要求填写心理 Schema。

`mentor_send(text, reply_to?)` 把 alice 选择发送的文字写入持久 outbox。Codex 取得消息后返回 ack，事件循环据此区分 `queued` 与 `delivered`；导师后续回答是新的接收 Event，不把“等待回答”冒充“已经获得回答”。

阶段三只接入 Shell 和导师文字。文件、进程和公开网络已经可以通过真实 Shell 使用；Chrome、Playwright MCP、微信、图片、语音、视频、硬件控制和专门网络适配器在本阶段不重复封装。以后新增的身体器官都遵循同一个规律：对外输出是 Action，执行后果重新作为 Event 返回。

### 5. 导师专用文字接口

`hominald` 在本机 Unix Socket `/run/hominal/hominal.sock` 提供极小 HTTP 接口，不监听公网端口：

```text
POST /v1/mentor/inbox                   Codex 向 alice 发送文字
GET  /v1/mentor/outbox                 Codex 读取 alice 的文字
POST /v1/mentor/outbox/<message_id>/ack Codex 确认已经取得
```

Codex 使用目标设备已经配置的 SSH 密钥直接调用这个本地接口；Genesis Lab 不复制、解释或改写消息，也不增加常驻中继服务。接口只接受 `message_id`、正文和可选 `reply_to`，由 `hominald` 添加实际接收时间、内部序号和通道来源。相同 `message_id` 重试只形成一次接收事实。

导师通道是当前唯一外部文字关系，不建设联系人、群聊、账号和应用层身份验证。SSH 密钥保证通道可信；说话者直接写在正文开头：

```text
[Codex代理导师]
……

[人类导师·经Codex传递]
……
```

Codex 自己形成的回答使用第一种前缀；导师要求原样转达的内容使用第二种前缀。不为这两个称谓建立 author Schema 或权限分支。

HTTP 处理器只把接收事实提交给事件循环。它不直接调用模型、不改变焦点，也不因“导师”来源获得命令优先权。阶段三工程模式可以把唯一导师消息作为测试焦点；阶段四开始由普通注意机制决定何时理解和回应。

### 6. 最低持久化

阶段三只保留两类运行事实：

```text
state/current.json       当前 revision、Pulse、最近事实快照、租约、未决动作和导师 outbox
journal/events.jsonl     ready、导师消息、认知、模型用量、动作、结果、恢复和异常
```

`current.json` 使用临时文件加 rename 原子替换；`events.jsonl` 只追加有意义的变化。外部健康检查继续读取轻量 heartbeat。单一事件循环是这些文件的唯一写入者。

总计划中的 `life.sqlite3` 三表不在本阶段预建。Concern 和 Commitment 尚未获得真实运行语义，现在建立空表只会提前固化猜测并引入新的构建依赖。阶段四继续使用原子文件；阶段五出现 Commitment、预测和现实学习的真实跨对象事务后，再决定是否一次性引入 SQLite。正式 `/life` 目录结构保留，但本阶段不制造叙事、记忆和作品占位内容。

导师输入的去重状态、alice 尚未被 Codex 确认取得的 outbox 和回复关联都随当前状态恢复。消息正文属于双方已经明确发送的外部对话，可以进入实例归档；SSH 密钥与其他凭据仍然不能进入。

### 7. 模型资源事实

每次 Responses 调用记录真实模型名、开始和结束时间、状态以及 API 返回的 input、output 和 total token 用量，不记录密钥。事件循环按滚动 60 分钟汇总 `total_tokens`，使用已经冻结的 `1,000,000` 上限。测试上下文和最大输出有明确上界，新调用必须为这次上界预留额度；剩余额度不足时不再启动调用，Pulse 和本地身体活动继续。

运行凭据由 Lab 在启动时写入实例之外的临时运行位置，停止和 reset 时清理，不进入 Birth Manifest、实例归档、日志或 Git。

### 8. 崩溃恢复

systemd 启动同一实例时，`hominald` 先读取 `current.json`。已经完成的事实继续保留；崩溃时仍在等待的模型请求记为中断；已经开始但没有可靠结果的动作记为 `unknown`，下一步只能重新观察现实，不能自动重复命令。

阶段二已经验证 systemd 的异常拉起和明确停止语义，本阶段只验证新进程能够恢复自己的状态，不重写 service 管理逻辑。

## 四、对现有代码的改动边界

本阶段预计只触及：

```text
body/cmd/hominald/       新的正式进程入口
body/internal/runtime/   同一 package 内的循环、感知、模型、动作、导师接口和存储
lab/run.py               从阶段二机械演练器收敛为阶段三构建与运行入口
deploy/                  仅在新进程确有启动参数需求时小改
tests/                   运行脊柱的确定性测试
```

`cmd/stage2-fixture` 作为阶段二实验证据保留，不继续扩写，也不进入阶段三发布包。`lab/run.py` 继续提供 `check / start / status / stop / reset`，不另建第二套 Lab 控制器。阶段二已经验证的归档、哈希、重启和 reset 逻辑直接复用。

阶段三不修改 Seed 和动力参数，不执行正式出生说明，不建立自动导师或消息中继服务，不生成 Birth Manifest，不操作番茄小说，不评价作品，也不扩建 lineage 研究数据库。

## 五、实施顺序

1. 用确定性假模型完成事件循环、Pulse、唯一租约和迟到结果测试；
2. 实现最小身体快照与 Difference Gate，验证相同读数不重复成 Event、实质变化不丢失；
3. 实现最小原子状态与事件记录，验证崩溃中间态恢复；
4. 接入真实 Responses API 和滚动 60 分钟用量账本；
5. 接入 `body_shell`、`mentor_send` 和动作结果回传；
6. 实现 Unix Socket 导师接口，由 Codex 通过 SSH 完成一轮真实收发与 ack；
7. 让 `lab/run.py` 构建并部署新的 `hominald`，复用现有 reboot、stop、archive 和 reset；
8. 在 Ubuntu 进行短时闭环、慢模型、事实变化、动作中断和进程崩溃测试；
9. 连续运行一小时，结束后保存归档并 reset；
10. 只修复阻断闭环的根本问题，通过退出门后冻结 `g0-stage3-v001`。

开发期间不等待一小时才发现基本错误：本地确定性测试通过后先运行五至十五分钟；短测稳定后只做一次正式的一小时工程耐久测试。

## 六、验证与退出门

阶段三完成必须同时满足：

1. `lab/run.py start` 能构建新的 `hominald`、部署当前实例并随 Ubuntu 重启自动运行；
2. 延迟超过十秒的模型请求和持续中的 Shell 动作不会阻断五秒 Pulse，ready 状态最大间隔不超过十秒；
3. Pulse 能形成最小身体快照；相同读数和微小抖动不重复形成 Event，磁盘、网络、器官、进程或额度的实质变化能够可靠进入 Event Inlet；
4. 事实差分只保存发生了什么，不在阶段三生成情感意义、Concern 或行动优先级；
5. 两个认知触发同时到达时只有一个模型认知在途，只有当前租约能够提交；
6. 被中止焦点的迟到结果不能覆盖新的 revision；
7. 至少一次真实模型调用在工程测试焦点中选择 root Shell 工具，实际退出结果和文件结果回到同一次认知并被记录；
8. Codex 通过 SSH 接口发送一条带 `[Codex代理导师]` 前缀的真实文字，消息只形成一个 Event，不绕过事件循环直接启动并发认知；
9. alice 至少一次选择 `mentor_send`，Codex 能读取并 ack，运行状态能够区分排队、送达和后续回复；
10. API 返回的真实模型与 token 用量进入滚动额度账本，SSH 密钥、模型密钥和其他凭据没有进入实例归档和日志；
11. 进程异常退出后恢复同一 `instance_id`，最近事实快照和未确认导师输出仍可读取，未知动作不会被自动重复；
12. 无变化 Pulse 不形成高频事件或模型调用，不存在自动网络信息流；
13. 在目标 Ubuntu 连续运行一小时没有并发提交、状态损坏、Pulse 中断、消息丢失或动作结果失联；
14. `stop`、归档和 `reset` 继续通过，结束后没有残留活动实例。

退出门只证明生命运行脊柱成立，不证明自主关注、情感动力、自我叙事或 CEB 已经出现。达到这些条件立即进入阶段四，不继续建设通用工作流、观察平台和未来工具抽象。

## 七、实际结果

阶段三已在目标 Ubuntu 上完成短测、故障测试和一次正式一小时工程耐久实验。正式样本为 `g0s3-20260824t152122z-c01f31`，归档位于离机 Genesis Lab 的 `archive/engineering/`。这份归档中的 release 哈希、实例终态、journal、systemd 日志和文件哈希是本阶段的权威证据。

正式耐久窗口持续 `3619.94` 秒，Pulse 从 `11` 增至 `735`，增加 `724` 次；journal 共 `21` 行，序号 `21/21` 唯一且最大序号为 `21`。窗口开始与结束 PID 均为 `2835`，`NRestarts` 均为 `1`，窗口内没有新增异常拉起。真实模型总用量为 `898` token，没有认知失败。一次 root Shell 行动创建了 `/life/stage3-endurance-proof.txt`，动作开始、完成、模型理解和导师消息均保持同一事件链。滚动额度在满 60 分钟后自然回收，没有停止生命脉冲。

短测还验证了导师收发与 ack、相同导师消息去重、认知途中崩溃、未知动作不自动重放，以及 journal 先落盘而状态文件尚未来得及更新时的序号重新对齐。测试过程中发现并从根部修复了两项问题：小额 token 变化被误判为身体事件，以及崩溃边缘下 journal 与状态序号可能重复。

阶段三退出门通过。停止、离机归档和 reset 已完成，目标设备随后进入阶段四工程实例。由于阶段三实施时工作树尚未单独形成 Git 提交，本阶段不虚构 `g0-stage3-v001` 标签；冻结依据是上述归档中的精确发布哈希。本次冻结源提交同时覆盖阶段三运行脊柱与阶段四动力学，发布二进制归档继续作为阶段三实机复现的直接证据。

## 八、导师配合

阶段三由 Codex 代理导师发送工程测试消息并接收一次 alice 回复；这只验收通道，不执行正式出生引导。人类导师通常不需要参与，只有当前模型凭据失效、Ubuntu 无法远程恢复，或执行会替换现有唯一系统快照的操作时才请求协助。阶段三不会主动触发微信手机确认，也不需要登录番茄小说。
