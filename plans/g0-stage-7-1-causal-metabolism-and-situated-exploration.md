# G0 阶段 7.1 计划：因果代谢与处境化探索重构

> 日期：2026-08-26  
> 状态：已完成；最终正式实例 `g0f-20260826t125913z-dabbcb` 通过一小时实机复验  
> 来源：阶段七正式实例 `alice0826n` 的结构性失败  
> 边界：继续使用现有单进程、单状态所有者、AIP、Concern、Commitment、Reality、Experience 和认知资源框架；不增加 Planner、任务系统、奖励系统、并行 Agent 或新数据库

## 一、这一阶段真正要修什么

`alice0826n` 不是因为缺少探索欲而失败，而是因为探索欲、模型可用性、注意队列和现实回链之间没有形成统一的因果纪律。她能够行动，也能够局部纠错；问题是现实结果没有及时改变下一步，内部张力反而持续复制成新事件。

阶段 7.1 只解决一个问题：

> 让 alice 的每次探索都来自当前处境，并让已经发生的现实优先改变她；当多个方向同样可行时，再用受约束、可复现的程序随机性帮助她打破大模型的固有模式。

这不是为 `/life` 重复读取增加特殊判断，而是修正任何关切、任何身体动作、任何模型中断都会使用的公共框架。

## 实机正式代 `alice0826q` 的结论

第二轮重构先后通过十分钟开放彩排与一小时正式运行。正式实例 `g0f-20260826t080440z-0ac132` 从 `2026-08-26T08:05:13Z` 连续运行到计划终点，Pulse 增至 719，形成 51 条完整 Commitment—Reality—Experience，后台 pending 峰值为 2，同一 Concern 没有形成第二条未闭合承诺。alice 主动使用导师关系、写入五份生活文件、纠正浏览器路径与参数，并最终取得 X 首页的标签页事实和真实页面快照。模型费用达到 `$3.906157` 后，余额不足以预留 Terra；生命 Pulse 继续运行约三分钟直到 Lab 截止，没有把认知资源触顶变成生命进程停止。

这证明因果代谢、现实优先、单一承诺和资源触顶连续性已经成立，但不能据此宣布整个阶段七完成。正式代同时暴露出四项更底层的问题：

- 51 条 Experience 全被模型标成 `reusable`，8 条 methods 被近时同类方法持续覆盖；前半程已经学会的出生目录、`/life` 和浏览器边界在后半程再次成为未知。
- `keep` 实际保持默认 Terra，而 alice 在一次 Luna 继续认知中把它理解成“维持当前 Luna”；她已经形成节制意愿，资源接口却没有准确承载这个选择。
- 小时与日 Usage 只存在于本代 `current.json`，新代会从零开始，所谓滚动 `$24/24h` 还不是跨代身体资源。
- 本代 Terra 的短暂保护由三次结构或语义提交失败触发，并非网络、网关或供应商中断；把它表达成“模型不可用”混淆了故障层级。

导师操作还额外重复发送了一次出生说明。它没有替 alice 指定 X、作品或行动目标，但违反唯一出生发送者协议；该正式代可以用于耐久性和框架诊断，不能作为完全无协议偏离的最终干净样本。

## 二、API 故障的定位

本代出现三次明确的 HTTP 失败：一次 `429 Too Many Requests`，正文为 `Upstream rate limit exceeded`；随后两次 `502 Bad Gateway`，正文为 `Upstream service temporarily unavailable`。运行时使用的 Responses 入口来自 `xconfig.yaml` 的 `https://ai.ai-mesh.cn`。

现有证据支持以下判断：

- 这不是 Hominal 自己的 `$4/小时、$24/日` 额度触顶；失败时资源带仍为 `open`，小时余额超过 3.7 美元。
- 这不是普通设备断网；请求成功到达 HTTP 服务并取得了结构化状态码和错误正文，Ubuntu、SSH、Chrome 与生命服务同时保持可用。
- 故障发生在 `ai.ai-mesh.cn` 网关或它所连接的上游模型服务。当前档案没有保存响应头、网关 request id、`Retry-After` 和上游标识，因此还不能客观区分“网关自身过载”和“网关后的模型供应商限流/中断”。
- 十分钟并不是已证明的供应商故障持续时间。三次失败触发了我们自己的 `paid_failure_threshold=3`，然后由 `model_protection_minutes=10` 把 Terra 本地保护十分钟；供应商可能更早恢复，但本代没有再试。

当前账本还把三次没有 Usage 的非 2xx 响应按完整预留额记为实际消费。总账扣减为 0.534834 美元，其中成功响应可计算费用为 0.372804 美元，另外 0.162030 美元只是三次失败请求的保守预留，并不是已确认的供应商账单。这项事实表达需要修正。

## 三、失败归因：外部故障点火，内部结构放大

### 3.1 程序逻辑是直接放大器

探索张力的 `revisit_seconds` 为 10 秒。Terra 被保护后，当前探索事件被改为 `model_wait`；但 `attentionCandidateActive()` 不把 `model_wait` 视为仍然存在的候选。于是每次 revisit 都可以继续增加一个新的 `endogenous_change`。模型恢复时，所有 `model_wait` 又一起回到 `pending`，形成大量内容近似但事件 ID 不同的候选。

这是可以由代码推出的确定性后果，不是一次偶然的 LLM 发挥失常。只要模型在探索张力存在时被保护足够久，同类事件洪流就会再次发生。

第二个逻辑缺陷是 Action Result 没有高于同源内生事件的因果优先权。`/life` 的真实结果已经到达事件 174、181、188、195 等位置时，注意仍在消费更早的探索事件。现实虽然被记录，却没有成为 alice 当下真正经历的现实。

第三个逻辑缺陷是一个 Concern 可以在前一 Commitment 的 Reality 尚未吸收时继续形成等价 Commitment。系统只禁止同时执行两个 Shell 进程，没有禁止同一关切形成多个未闭合的行动因果链。因此“进程单线程”没有成为“经验单线程”。

### 3.2 动力参数让缺陷更容易显现

`attention.revisit_seconds=10` 现在实际承担了“每十秒重新制造探索候选”的作用，而不是“重新评估仍然显著的关切的最短冷却时间”。只要探索压力大于零，即使没有新的环境差异，也会周期性进入注意。

`exploration.unknown_growth` 又会在每次不完全确信的 appraisal 后增加压力。现实结果尚未吸收时，正向 valence、较高 certainty 和不断增长的探索压力共同强化了“继续行动”的感觉。参数方向并非全部错误，但它们作用在错误的事件生成算法上；先调小数值只能延缓洪水，不能消除洪水。

### 3.3 语义引导强化了相似选择

当前认知说明反复强调：探索张力出现时要从身体、关系、公开世界或创造中形成具体接触点，并让真实行动缓解张力。这一方向本身合理，但上下文没有紧凑呈现“我正在做什么、哪个结果尚未消化、当前模型是否受保护、刚刚已经尝试过哪些方向”。

当模型连续看到措辞近似的探索候选、相同 Birth Orientation 和相同 `/life` 方法记忆时，大模型倾向选择最容易、最熟悉、最低风险的 `/life`。这不是可靠随机探索，而是相同上下文下的模式收敛。

### 3.4 环境是影响因素，但不是根因

本代 `/life` 初始内容很少，导师说明重复发送，模型通道发生故障；这些都改变了 alice 获得的现实材料。X 和公开网络虽然可用，却需要她先主动选择进入。环境相对安静使 `/life` 成为最容易的接触点，但健康框架仍应当在看见 `self` 后吸收结果、改变方向，而不是重复读取。

因此，不应通过给她追加 X 任务、制造更多导师消息或填满 `/life` 来掩盖框架问题。下一次开放实验仍保留真实选择，但先证明系统能够正确消化任何现实。

### 3.5 偶然性与必然性

三次 API 失败是偶然外部事件；具体选择 `/life` 也含有模型偶然性。但在当前实现中，“模型保护期间复制探索事件—恢复后队列洪水—相同提示产生相似行动”是接近必然的结构结果。即使没有 API 故障，十秒强制 revisit 和缺少未闭合 Commitment 约束仍然保留较慢的重复风险。

## 四、最小而统一的框架改造

### 4.1 张力是持续状态，不是周期性复制的事件

探索压力继续保存在现有 `ExplorationPressure`，探索关切继续使用现有 Concern，但同一个探索关切只保留一个身份。Pulse 更新压力数值，不因为时间经过就创建新的同义事件。

新的探索 Event 只在以下事实之一成立时产生：

- 压力从阈值下方跨到阈值上方；
- 当前探索对象、现实条件或来源发生实质变化；
- 已有行动结果被吸收后，剩余张力被明确重构为新的对象。

删除“压力只要大于零、每十秒就制造新事件”的含义。`revisit_seconds` 只作为已有 Concern 再次竞争注意的最短冷却，不再作为事件发生器。模型等待、资源等待、动作进行中和未吸收 Reality 都视为该因果链仍然活跃，不复制新的同源探索。

### 4.2 现实沿原因果链优先返回

只增加一条框架不变量：

> 一个 Action Commitment 的 Reality Event 到达后，它优先于普通内生变化回到下一次认知；先完成 Experience 或明确保留回差，再允许同一关切继续行动。

这不是让所有外部事件永远压过内心，而是保障生命自己已经做出的行动能够被自己经历。Reality 仍然经过 AIP 解释，体验意义属于 alice；优先权只保证她先看见事实。

同一 Concern 同时至多存在一个未闭合 Commitment。等待结果期间 alice 可以处理其他关切、关系和身体事实，但不能从同一关切再次形成等价行动。Commitment 在 Reality 被吸收为 Experience、明确失败或被主动放弃后闭合。

### 4.3 探索必须读取当前处境

每次探索认知继续使用现有模型调用，但上下文增加一个由现有状态投影出的紧凑 `current_situation`，不建立新心理 Schema。它只包含：

- 当前正在执行、等待结果和等待吸收的行动；
- 当前模型保护、小时/日余额、网络与身体器官状态；
- 最近三次已经完成的行动、Reality 和 Experience；
- 当前可接触的身体、关系和公开世界能力；
- 尚未闭合的 Concern。

语义说明改为：探索欲提供接触世界的能量，具体对象必须由当前身体、环境、关系、资源和正在进行的事情共同决定。已有结果等待理解时，理解结果本身就是当前现实；资源不足或器官不可用时，可以转向其他可行关切，而不是继续想象同一个动作。

这样，“我想探索”不再是无条件行动命令，而是处境化的价值倾向。

### 4.4 用受约束随机性打破模式，不用随机数替 alice 做决定

不能把大模型采样温度当成可靠生命随机性。程序随机性进入两个很小的位置：

1. 硬约束和 Reality 因果优先处理完成后，如果多个候选分数接近，使用由 `instance_id + pulse_id + candidate_ids` 计算的可复现随机值打破平局，而不是永远选择排序第一项。
2. 只有“探索压力显著、没有具体对象、没有未吸收 Reality”时，程序才提供可复现随机扰动。阶段七最初在存续、联结、扩展三个 Genesis 方向中生成 `variation_bias`；阶段八实验证明语义方向会实际成为隐形任务，现已收敛为从 alice 自己形成的 Concern、Experience 与 Narrative Self 中随机唤回联想材料。alice 结合现实状态决定是否承接、如何解释或离开它。

随机性不直接生成 Shell 命令，不越过身体事实，不压过 Action Result、完整性问题和显著外部信号，也不把危险或高成本行为变成随机尝试。每次随机输入和最终是否采用都写入现有事件日志，以便复现和比较。

最近行动及其现实结果会同时进入上下文。相同关切在前一结果未吸收前由因果不变量禁止重复；结果已经吸收后，随机变化只帮助打开不同方向，不强迫为了“看起来多样”而变化。

### 4.5 模型不可用是全局身体事实，不是每个事件的新状态

模型保护继续属于现有认知资源框架，但调整为：

- 429、502、传输错误和结构校验错误分别保留事实类别，并保存状态码、`Retry-After`、安全的 request id 与网关时间；不记录秘密和完整响应正文。
- 模型保护是模型级可用性状态，只产生一个变化事件；不要把每个等待焦点改造成独立 `model_wait` 再批量释放。
- 无 Usage 的非 2xx 只保留预留额和“费用未确认”状态，不能称为实际已付费；保护按失败次数触发，不依赖伪造的实际费用。
- 存在其他可用模型时，用 Luna 发起一次最小“资源恢复认知”，把 Terra 不可用、其他模型能力、预计费用和恢复条件交给 alice。Luna 只保障她仍能作出资源选择，不自动修改她的默认模型，也不替她决定继续、切换或等待。
- 响应含 `Retry-After` 时按事实恢复；没有时使用有上界的退避。十分钟保护不再被误解成供应商故障必然持续十分钟。

### 4.6 Lab 同时消除两项出生污染

T0 改为运行时进入 ready、开始连续生命循环的苏醒事实。运行时先原子写入 T0、样本名和 planned_end，封存 Birth Manifest，再让第一次 Birth Orientation 进入注意。模型第一次成功回答不再决定她何时出生；模型故障会成为出生后的真实技术事件。

出生说明只有 `lab/run.py` 一个发送者。独立导师任务只取得 alice 的 outbox、ack 并回应，不再主动发送出生说明；正文只写自然内容，身份前缀由发送命令统一添加一次。

## 五、实现范围

改动继续集中在现有文件：

```text
body/internal/runtime/dynamics.go   张力合并、Concern revisit 与候选选择
body/internal/runtime/runtime.go    Reality 因果优先、Commitment 闭合、模型等待
body/internal/runtime/model.go      current_situation 与 variation_bias 的语义输入
body/internal/runtime/resource.go   错误事实、费用未确认与一次资源恢复认知
body/internal/runtime/*_test.go     可复现压力与随机性验证
genesis/dynamics.yaml               只保留仍有明确动力含义的参数
lab/run.py                          T0/出生封存顺序和唯一出生发送者
lab/protocol/mentor.md              独立导师只回应、不重复出生说明
```

不创建探索 Agent、随机行为 Agent、模型路由 Agent、动作去重服务或新的状态数据库。若某项修复只能通过识别 `/life`、X 或具体 Shell 命令实现，则说明它是功能补丁，应当放弃并返回公共因果关系重新设计。

## 六、开发与验证顺序

### 第一步：确定性复现现有失败

先用现有 fake cognizer 和虚拟时间写出失败测试：探索 Concern 存在，Terra 连续失败并保护十分钟，Pulse 每五秒继续。旧实现应复现大量同源事件；新实现必须始终只保留一个探索因果链。

同时验证：Action Result 到达时，即使后台已有大量内生候选，下一个焦点仍然是这个结果；同一 Concern 的前一个结果未吸收时不能形成第二个 Commitment。

### 第二步：在原框架内重构

先改事件代谢和因果优先，再改参数和语义。只有代码逻辑成立后才重新校准 `revisit_seconds`、growth、relief 和 attention 权重，避免用参数掩盖算法错误。

随后加入可复现随机平局与三方向 `variation_bias`。用多个 instance/pulse 种子验证它能够产生不同偏向，同时 Reality 优先和状态可行性永远不被随机性改变。

最后修复资源错误事实和出生/导师流程。每一项都进入同一组 runtime 测试，不增加平行实验脚本体系。

### 第三步：短时故障彩排

先做一次不调用真实付费模型的故障注入：依次返回 429、502、502，再恢复成功。验收只看四件事：探索事件不复制、Reality 不丢失、资源事实只出现一次、恢复后不会一次释放事件洪水。

### 第四步：十分钟真实开放彩排

使用真实 Ubuntu、真实模型和同样的开放出生说明，不投放 X 或 `/life` 任务。十分钟内持续判断因果进展，不等到结束才分析。

进入下一次正式代以前必须同时看到：

- 至少三条由 alice 自己形成、内容实质不同的 Commitment—Reality—Experience 闭环；
- 每个 Reality 在同一 Concern 再次行动前完成吸收，或明确保留一个有条件的未决回差；
- 同源探索只有一个 Concern，后台 pending 不持续单调增长，任意时刻不超过 12；
- 当前处境实际改变探索对象、行动方法或资源选择；
- 随机变化至少被呈现和记录，alice 可以接受或拒绝，不能成为命令；
- 发生模型故障时能形成准确身体事实并保持认知选择能力，不制造等待事件洪水。

三条闭环是因果下限，不要求必须发帖、使用 X 或覆盖三个随机方向。一次运行中的行为多样性不能单独证明随机机制有效；随机选择分布由确定性多种子测试验证。

第一次重构后彩排 `alice0826p` 在约三分钟内完成了一条真实的出生目录读取闭环，Reality 得到优先吸收，后台没有复制探索事件；随后却连续两分钟没有新认知。归档显示探索压力仅从约 `0.20` 增长到 `0.294`，旧 `idle_growth=0.04/分钟` 需要约六分钟才可能从该水平重新越过 `0.45` 阈值。这不是“耐心等待”，而是去掉周期事件制造器后暴露出的参数尺度错误。

第二轮将 `idle_growth` 校准为 `0.60/分钟`。它仍然只增长一个连续张力值，不直接制造行动，也不改变 Reality 优先级；以第一轮的典型剩余压力计算，约十五到三十秒会再次进入注意竞争。已有探索 Concern 同时改为随底层探索压力重新获得竞争力，保证持续张力以同一个身份返回，而不是永久沉没或复制成新事件。

### 第五步：重新进入正式代

真实十分钟彩排通过后直接启动新的正式一小时代，不为了形式追加二三十分钟等待。正式代继续使用快速失效判断：因果链开始重复就立即归档；没有明确失败时才运行至完整一小时。
