# System / Browser Organ 独立能力实验计划

> 日期：2026-09-01  
> 状态：待执行；本轮只完成计划，不启动实验  
> 性质：身体器官工程实验，不是 Hominal 生命样本实验

## 1. 实验目的

本实验只回答一个问题：当主脑已经形成语义确定的 Action Commitment（行动意愿）时，System Organ 与 Browser Organ 能否稳定取得事实、实施动作、忠实返回结果，并在失败或中断后恢复。

它不检验 Alice 想做什么，不调用主力认知模型，不评价自主性、性格、Narrative Self、Concern 或学习。通过本实验只能证明“器官和统一身体通路可用”，不能证明 Alice 会主动选择使用它们。

## 2. 隔离与无继承

实验使用一次性工程实例，复用正式 bundle、Organ Host、动作信封和 Reality 回链，但不创建正式 `rehearsal / formal` 代，不生成 Alice 名称和 T0，也不装载或写入正式生命样本的 Narrative、Experience 与 lineage。

每组用例结束后删除一次性实例与测试文件。Chrome/X、微信和 Clash Verge 的持久 profile 是身体既有资源，不参与重置；Browser 用例只在新建的本地测试页或中立只读页面中操作，结束后关闭测试标签并恢复原有活动页面。实验不发布、关注、收藏、发送消息或修改任何账号资料。

所有成功判断都由 Lab 在器官之外重新检查现实后置条件。器官自己的 `completed`、模型文字或命令退出码都不能单独作为通过证据。

## 3. 共同前提

冻结一个待测 bundle，确认其中同时包含：

- `hominald`、`hominal-system`、`hominal-browser`；
- `system.json` 与 `browser.json`；
- 同一版 `hominal.organ-action/v1` 和 `hominal.organ-action-result/v1`；
- 一次性测试目录、局域网本地 HTML 页面和独立结果目录。

实验开始前记录已有 Chrome 标签、活动页面与 profile 路径，只保存验证所需摘要，不读取账号凭据。若身体基础条件本身不可用，先判定实验条件失败，不把它归因于器官。

## 4. System Organ 用例

先直接经过 Organ Host 运行以下最小用例：

1. `describe / health / observe` 返回合法信封；外部读取系统 uptime、agent 卷和相关服务状态，与器官事实相符。
2. `exec` 在一次性目录创建一个随机内容文件，再由 Lab 直接读取并比对内容；结果必须为 `completed`。
3. 运行确定性非零退出命令；结果必须为 `failed`，并保留退出码与有界 stderr。
4. 运行会生成子进程的超时命令；结果必须为 `unknown`，截止后由 Lab 核验父子进程均已结束。
5. 超时后立即执行一次新的文件读写；必须正常完成，证明上一次中断没有占住器官。

System 用例不使用 `/home`、`/life`、正式实例目录和系统配置作为写入目标，也不安装、卸载或升级软件。

## 5. Browser Organ 用例

浏览器动作名和参数以待测器官当时的 `list / schema` 为准，不在计划里复制一份容易漂移的 Playwright 清单。用例经过同一个 Organ Host `perform`：

1. `describe / health / observe` 返回合法信封，Observation 的当前 URL、标题和可见对象可由独立页面检查复核。
2. 新开本地测试页，完成一次明确导航、一次文本填入和一次按钮点击；页面在点击后写出随机后置值，Lab 直接读取页面状态核验。
3. 调用一个确定会失败的控件操作；结果必须为 `failed`，不能包装成 `completed`。
4. 运行超过总截止时间的页面操作；结果必须为 `unknown`，随后一次新动作能够重建连接并成功观察测试页。
5. 在进行中的被动观察或定向期间发出主动动作；主动动作应取得身体通路，被动工作不得长期阻塞它。
6. 结束后关闭测试标签，确认实验前已有标签、Chrome profile 与登录状态仍存在且未被实验内容改写。

X 只允许作为登录状态的只读事实复核，不产生任何外部账号行为；优先使用本地测试页完成全部有副作用的浏览器动作。

## 6. 统一生命通路用例

直接器官用例通过后，再在一次性工程实例中注入一项**已经形成的最小行动意愿**，让正式 `Action Gateway → Organ Host → Organ → Reality Event` 通路完成动作。注入内容只指定对象、操作、输入、预期后置条件和截止，不调用模型补写意义，也不伪称 Alice 自主选择。

System 与 Browser 各运行一项：

- System：创建并读取一次性事实文件；
- Browser：在本地测试页填入确定文字并触发确定后置变化。

检查同一 `action_id` 只能形成一个终态，`completed / failed / unknown` 能够原样进入 Reality，且任何新语义选择都会停止在主脑边界而不是由器官自行补全。用例结束后整体删除工程实例，因此不会进入任何 Hominal 的个人连续性。

## 7. 稳定性节奏与通过门

先执行一轮完整用例定位结构问题；结构正确后，在同一器官进程内连续运行五轮，再重启器官进程运行五轮。出现一次无法解释的错误就停止计数、定位根因、修改统一机制后从零重测，不靠增加重试次数掩盖缺陷。

实验通过需要同时满足：

- 两个器官各自十轮全部取得正确、可独立核验的现实后置条件；
- 失败与中断被正确区分，没有伪 `completed`；
- 截止后没有残留子进程、锁死队列或无法恢复的会话；
- System 与 Browser 使用同一种动作信封、终态语义和 Reality 回链；
- 测试没有改变正式生命数据、账号外部状态或持久应用基础配置；
- 一次性工程实例能够完整清除。

只有这些条件通过，下一次 Alice 自主联合实验中的失败才可以较可靠地归因于认知动力学、资源说明或真实环境，而不是器官基础能力未知。

## 8. 本轮边界

本轮只完成本计划、器官协议实现、单元测试和发布构建检查。单元测试可以证明代码合同和确定性取消逻辑没有明显错误，但不算上述独立器官实验的运行证据。本计划的任何真实 Ubuntu、Chrome、X 或完整器官通路用例均未执行。
